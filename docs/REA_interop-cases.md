## Cценарии использования (use-case)

Предлагаемые сценарии расширяют базовые примеры из документации и ориентированы на практическое внедрение в инженерно-производственные контуры.

### **Сквозная валидация спецификаций в многоуровневой кооперации**  
Головной исполнитель формирует и публикует профиль уровня B/C. 
Субподрядчики второго и третьего уровней автоматически проверяют свои ведомости покупных изделий на соответствие допущенной ЭКБ перед передачей данных наверх. 
При отклонении от порога интероперабельности система блокирует экспорт пакета данных и формирует перечень расхождений для согласования.

### **Управление приоритетами импортозамещения в реальном времени**  
При изменении статуса доступности иностранных компонентов (санкционные ограничения, прекращение производства) уполномоченный орган обновляет `ReplacementGroup` в центральном профиле. 
Интегрированные PLM-системы участников кооперации автоматически пересчитывают допустимые аналоги, обновляют статусы `priority` и уведомляют инженеров о необходимости корректировки конструкторской документации.

### **Интеграция с государственными и отраслевыми реестрами**  
Использование модуля привязки `eskd_binding.xsd` для автоматического сопоставления внутренних справочников ЭКБ с внешними реестрами (например, реестр Минпромторга, базы ФАУ «РСТ», отраслевые перечни разрешённой продукции).
Профиль выступает каноническим промежуточным форматом, обеспечивающим семантическую согласованность при обмене с регуляторными информационными системами.

### **Формализованный приёмочный контроль опытных образцов**  
При передаче изделия на квалификационные или приёмочные испытания генерируется машиночитаемый протокол соответствия уровня C. 
Испытательные центры используют данный протокол для автоматической проверки комплектации образца, что исключает ручную сверку спецификаций и ускоряет допуск к тестированию.

### **Миграция и синхронизация данных при замене PLM/ERP-платформ**  
При переходе предприятия на новую систему управления данными или при интеграции разнородных платформ (например, отечественная PLM + legacy ERP) профиль применяется как эталонная модель обмена. 
Это обеспечивает сохранение семантики атрибутов ЭКБ, статусов допуска и связей с нормативными документами без потери информации в процессе трансформации.

### Верификация комплектации при разработке РЭА
**Контекст:** Инженер-конструктор формирует спецификацию изделия в САПР, интегрированной с системой управления данными (УДИ/PLM).

**Процесс:** 
  1. Система генерирует `ComplianceAssertion` для изделия, ссылаясь на актуальный `AllowedComponentList`.
  2. Автоматическая валидация через XSD + Schematron проверяет: - Наличие всех обязательных атрибутов компонентов - Соответствие статусов допуска (`approvalStatus ≠ prohibited`) - Целостность ссылок на нормативные документы
  3. При уровне интероперабельности ≥B система формирует протокол соответствия для передачи в отдел нормоконтроля.

**Эффект:** Снижение риска использования неразрешённых компонентов на этапе проектирования.

### Межорганизационный обмен перечнями при импортозамещении
 **Контекст:** Головной исполнитель и субподрядчик обмениваются данными о допустимых заменах иностранных компонентов на отечественные аналоги. 
 
 **Процесс:** 
  1. Головной исполнитель публикует `ReplacementGroup` с приоритизированными аналогами (`priority=1` для предпочтительных).
  2. Субподрядчик импортирует профиль в свою УДИ, используя `eskd_binding.xsd` для маппинга ссылок.
  3. Система автоматически проверяет: - Совместимость версий профилей (`profileVersion`) - Наличие расширенной информации в атрибутах уровня B (`manufacturer`, `qualificationStatus`)
  4. При расхождении в степени интероперабельности генерируется отчёт о несоответствиях для согласования.

**Эффект:** Стандартизированный обмен данными без потерь семантики при смене платформ.

### Аудит соответствия при сертификации изделия 

**Контекст:** Орган по сертификации проверяет документацию на соответствие требованиям по применению разрешённой ЭКБ. 

**Процесс:** 
  1. Заявитель предоставляет пакет данных в формате профиля ЭКБ с уровнем интероперабельности C.
  2. Валидатор проверяет: - Прохождение всех правил Schematron (включая бизнес-правила: `effectiveDate ≤ verificationDate`) - Полноту заполнения рекомендуемых атрибутов (`≥90%`) - Корректность маппинга между модулями 2.525 и 2.058
  3. Формируется машиночитаемый протокол аудита с указанием степени интероперабельности и перечнем замечаний.
    
**Эффект:** Автоматизация проверки, снижение субъективности аудита, ускорение сертификации.
