## 4. 4.2 Основная структура сборочной единицы (одноуровневая структура) ^(Стр. 10)


4.2.1 Основная структура СЕ– это совокупность вхождений всех СЧ (в т.ч. материалов в сборке) в эту СЕ. ^(Стр. 10)


Примечание — рассматриваются СЧ на один уровень разукрупнения вниз. ^(Стр. 10)


4.2.2 Для описания каждого вхождения СЧ в СЕ используется ИО next_assembly_usage_occurrence, который наследует все атрибуты ИО assembly_component_usage (рисунок 2). ^(Стр. 10)


4.2.3 Возможны два способа указания количества, в котором СЧ входит в вышестоящую СЕ: ^(Стр. 10)


- описание каждого отдельного вхождения СЧ отдельным экземпляром ИО next_assembly_usage_occurrence. (т. е. создание стольких экземпляров объекта, сколько штук конкретной СЧ входит в изделие); ^(Стр. 10)


- использование комплексного ИО next_assembly_usage_occurrence + quantified_assembly_component_usage, в дополнительном атрибуте «quantity» которого указывается количество (с учетом применяемой единицы измерения) СЧ, входящих в «родительскую» СЕ. ^(Стр. 10)


Первый способ не может применяться для описания вхождений материалов и других изделий, количество которых измеряется не в штуках. ^(Стр. 10)

## 4. 4.3 Описание допустимых замен ^(Стр. 12)


4.3.1 Если вместо одной СЧ в составе СЕ может использоваться другая СЧ (допустимая замена), то все такие СЧ включают в состав СЕ как отдельные вхождения, после чего информацию о допустимой замене приводят с использованием ИО assembly_component_usage_substitute (допустимая замена) – см  рисунок 2. ^(Стр. 12)


4.3.2 В атрибуте base указывают основную СЧ, а в атрибуте substitute – допустимую замену основной СЧ в составе данной конкретной СЕ. ^(Стр. 12)


4.3.3  Если  необходимо  указать  несколько  допустимых  замен  с  разными приоритетами  использования,  то  используют  ИО ^(Стр. 12)


assembly_component_usage_substitute_with_ranking (см. рисунок 2), который позволяет для допустимой замены указать ее приоритет в виде целого числа в атрибуте ranking. ^(Стр. 12)


4.3.4 Если вариант изготовления СЕ представляет собой замену одной СЧ несколькими СЧ, то информацию о такой замене приводят с использованием ИО assembly_component_usage_substitute_with_ranking, в котором все заменяющие детали помечают одним числом в атрибуте «ranking», а в атрибуте «ranking_rationale» приводят соответствующие пояснения: «Применять с позициями … взамен позиции …». ^(Стр. 12)


## 4. 4.4 Подбор СЧ ^(Стр. 12)


4.4.1 Если при изготовлении СЕ для регулировки, настройки, компенсации требуется подбор СЧ, то указание таких СЧ в структуре СЕ выполняют способами, описанными ниже. ^(Стр. 12)


4.4.2 Если подбор производится одинаковыми СЧ (например, требуемая нагрузка пружины достигается установкой под нее набора одинаковых шайб), то в состав СЕ такие СЧ включаются с помощью комплексного ИО next_assembly_usage_occurrence + quantified_assembly_component_usage с указанием в атрибуте quantity наиболее вероятного количества таких СЧ, а в атрибуте description приводят соответствующую запись: «Подобрать необходимое количество …» (например, «Подобрать необходимое количество для обеспечения нагрузки пружины»). ^(Стр. 12)


4.4.3 Если подбор производится установкой одного из изделий, имеющих разные размеры и самостоятельные обозначения (например, величина зазора должна обеспечиваться установкой только одного установочного кольца), то в состав СЕ включают все необходимые подборные изделия  с использованием ИО next_assembly_usage_occurrence, у которых в атрибуте description приводят соответствующую запись «Подбор из группы СЧ». Все подборные СЧ связывают с одним из вариантов (условно выбранным в качестве наиболее вероятного) с использованием ИО assembly_component_usage_substitute. ^(Стр. 13)


Наиболее вероятный вариант указывают в атрибуте base каждого объекта assembly_component_usage_substitute, а в атрибуте definition указывают «Подборные СЧ». ^(Стр. 13)


4.4.4 Если подбор производится установкой нескольких изделий с различными размерами, обозначениями и в различных количествах, то в состав изделия включают все подборные СЧ с использованием комплексного ИО next_assembly_usage_occurrence + quantified_assembly_component_usage с указанием в атрибуте quantity наиболее вероятного количества каждой СЧ, а в атрибуте description приводят соответствующую запись: «Подобрать необходимое количество …». Все варианты СЧ, выбираемые подбором, связывают с одним из вариантов (условно выбранным в качестве наиболее вероятного) с использованием ИО assembly_component_usage_substitute. Наиболее вероятный вариант указывают в атрибуте base каждого ИО assembly_component_usage_substitute, а в атрибуте definition указывают «Подборные СЧ». ^(Стр. 13)


## 4. 4.5 Указание зависимости между двумя составными частями одной сборочной единицы ^(Стр. 13)


4.5.1 Если установка в СЕ одной СЧ зависит от установки другой СЧ, то в основную структуру добавляют все варианты СЧ (как описано в 4.3 или 4.4) и устанавливают связи между такими зависимыми вхождениями. Для описания такой связи используют ИО product_definition_usage_relationship (см. рисунок 1), связывающий два ИО product_definition_usage  (соответствующие двум СЧ  одной СЧ). ^(Стр. 13)


Примечание – Для обеспечения связи между двумя СЧ одной СЕ необходимо, чтобы в атрибуте relating_product_definition каждого из двух связываемых экземпляров ИО product_definition_usage был указан один и тот же экземпляр ИО product_definition. ^(Стр. 13)


## 4. 4.6 Описание конкретного вхождения одного изделия в состав другого изделия ^(Стр. 13)


4.6.1 В некоторых случаях, когда одно и то же изделие входит в состав другого изделия несколько раз, требуется каждый такой случай описать отдельно. ^(Стр. 13)


Пример — в СЕ «ходовая часть автомобиля» может входить  изделия «шасси» и «колесо». При описании структуры изделия «ходовая часть автомобиля» создаются 4 экземпляра ИО assembly_component_usage, каждый из которых ссылается на описание (product_definition) одного и того же колеса. При этом атрибуты reference_designator каждого вхождения колеса имеют собственные значения: ‘левое переднее’, ‘правое переднее’, ‘левое заднее’, ‘правое заднее’, соответственно. При необходимости может быть создано отдельное описание (product_definition) одного из колес, например, левого переднего колеса, которое может быть связано с конкретным вхождением в структуру – вхождение с идентификатором ‘левое переднее’. ^(Стр. 14)


4.6.2 Для описания конкретного вхождения СЧ в структуру СЕ используется ИО product_definition_occurrence_relationship (см. рисунок 2). При этом в атрибуте occurrence_usage указывается ссылка на конкретное вхождение в структуре, а в атрибуте occurrence – ссылка на необходимый product_definition. ^(Стр. 14)

6 Описание концепции изделия ^(Стр. 19)


6.1 Схема product_concept_schema на языке Express для идентификации и описания концепции изделия приведена в ГОСТ Р ИСО 10303-44.  Ниже приводится описание применения данной схемы для формализации концепции изделия машиностроения (конечного изделия), разрабатываемого в соответствии со стандартами ЕСКД. ^(Стр. 19)


Краткое формализованное описание product_concept_schema на языке Express (ГОСТ Р ИСО 10303-11) приведено в Приложении А.2. ^(Стр. 19)


6.2 Описанная ниже схема данных предназначена для описания «облика» конечного изделия на уровне концепции или идеи без привязки к конкретной реализации или исполнению. Концепция изделия формируется на самой ранней стадии жизненного цикла изделия, до начала его разработки, согласно ГОСТ Р 77.102. ^(Стр. 19)


Концепция изделия определяет набор характеристик или функций нового изделия, необходимых для решения определенной задачи или удовлетворения потребностей потребителя. Для этих характеристик, возможностей и функций могут быть заданы взаимосвязи и условия, определяющие их допустимые сочетания и порождающие возможные варианты конструкции конечного изделия в рамках одной концепции. ^(Стр. 19)


Понятие «концепции» и ее структурированное описание позволяет обеспечить основу для управления требованиями и конфигурацией на ранних стадиях разработки. Концепция изделия может включать несколько объектов конфигурации. ^(Стр. 19)


Примечание – Например, автомобиль может иметь два типа двигателей, которые могут быть идентифицированы как характеристики изделия. Один из них - двигатель меньшей мощности, другой - двигатель большей мощности. Установка системы кондиционирования воздуха (опция) может требовать установки двигателя большей мощности. ^(Стр. 19)


6.3 Для описания концепции изделия используются следующие основные ИО (рисунок 9): ^(Стр. 19)


/ ^(Стр. 20)


Рисунок 9 ^(Стр. 20)


- product_concept — концепция изделия, описывающая изделие в абстрактном виде, не касающаяся деталей конструкторской реализации. ^(Стр. 21)


- product_concept_relationship — связь между двумя концепциями изделия, например,  «часть-целое», «вариант», «альтернатива». Позволяет описывать структуру, зависимости и взаимосвязи на уровне концепций. ^(Стр. 21)


- product_concept_feature — характеристика, возможность или функция изделия, используемая в концепции (далее – опция). ^(Стр. 21)


6.4 Концепция изделия может допускать производство нескольких вариантов изделия, формируемых из выделенных в этой концепции опций и их допустимых сочетаний. ^(Стр. 21)


Пример — пусть предполагается разработать новую модель автомобиля, описываемую с использованием ИО product_concept. Эта модель может выпускаться с дизельным (DE) или бензиновым двигателем (SI). Автомобиль может быть оснащен системой кондиционирования воздуха (AC) и электрическими стеклоподъемниками (EW), однако эти опции требуют более ёмкой аккумуляторной батари (SB). Для описания опций используется ИО product_concept_feature. Условия  использования конкретных опций описываются  при помощи ИО conditional_concept_feature, а допустимые сочетания опций  – при помощи ИО concept_feature_operator. ^(Стр. 21)

Объект конфигурации может соответствовать одному  из вариантов концепции изделия, всей концепции изделия или ее части. Ссылка на концепцию изделия устанавливается в атрибуте item_concept ИО configuration_item. ^(Стр. 22)


7.5 Подтипом ИО configuration_item является ИО configurable_item (вариативный объект конфигурации) – это объект конфигурации, с которым связан набор опций (product_concept_features), предусматриваемых концепцией изделия. ^(Стр. 22)


Примечание – Например, заказ клиента на автомобиль может указывать модель заказанного автомобиля, а также его требуемые  характеристики: цвет - «красный», отделка салона - «серая кожа», люк в крыше и алюминиевые диски. 7.6 Для описания конкретной конфигурации используется ИО configuration_effectivity, оперирующий серийными номерами изготовленных изделий (ИО serial_numbered_effectivity), датами изготовления изделий (ИО date_effectivity) и принадлежности изделий к определенным партиям (ИО lot_effectivity). ^(Стр. 22)
